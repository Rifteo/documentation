## What is AuditGuard Community?

**AuditGuard Community** is the open community hub built around AuditGuard — a place where security professionals contribute, share, and maintain skills, scripts, and compliance workflows.

While **AuditGuard** is the core engine that runs skills and produces structured audit outputs, **AuditGuard Community** is where those skills live, grow, and get peer-reviewed. Anyone can contribute a skill, report an issue, or propose improvements. The goal is a shared, high-quality library that covers every phase of a security engagement — from scoping and recon through exploitation, scoring, and reporting.

## What's in the Community Hub?

| Resource | Description |
|---|---|
| **Skills** | Reusable, self-contained methodology units for pentesting, bug bounty, compliance, and reporting |
| **Scripts** | Automation scripts that support skill execution — scanners, payload generators, report parsers |
| **Contexts** | Pre-configured skill bundles for specific engagement types (web app pentest, API review, cloud audit) |
| **Workflows** | Ordered sequences of skills executed together as a single audit or engagement run |

## AuditGuard vs. AuditGuard Community

| | AuditGuard | AuditGuard Community |
|---|---|---|
| **What it is** | The core platform and CLI | The open skill and script library |
| **Who maintains it** | AuditGuard team | Community contributors |
| **Where it lives** | The AuditGuard platform | This documentation hub + GitHub |
| **What you do with it** | Run skills, generate reports | Contribute skills, find methodologies, benchmark quality |

## How Skills Work

1. A **skill** is a self-contained methodology — it defines what to test, how to test it, and how to report the result
2. Skills are installed via the CLI: `auditguard-skills add <skill-name>`
3. Skills are run inside an AuditGuard engagement context, producing structured findings
4. Community skills are peer-reviewed and benchmarked before being listed here
